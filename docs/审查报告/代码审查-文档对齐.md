# 代码审查：文档 × 实现对齐

> **审查对象**：`立项.md` 的功能主张 × `src/` 的实际实现（60 个源文件 / 26,772 行）
> **审查口径**：文档里写的每一条**可核对的主张**（标识符、行为路径、依赖声明），在代码里**是否成立**。
> 重点抓两类：① 文档承诺但代码没有（漏实现）；② 文档说"复用 X"但代码自研（违反复用纪律）。
> **一次性结论**：**真实偏差 3 处**，误判 5 处（工具口径造成，已记入方法论）。

## 5. 方法论：5 处误判与工具口径

这轮审查里，**假阳性/假阴性都出现过**，值得记下来：

| # | 现象 | 原因 | 纠正 |
|---|---|---|---|
| 1 | 搜 `lib/client.js` 找新代码 → **0 命中**，一度得出"产物没更新" | PowerShell `Select-String` 对该 UTF-8 文件的匹配口径不对 | 改用 `[System.IO.File]::ReadAllText` |
| 2 | 搜 `StatePlayIcon` 在产物里 0 命中 | 同上（错误编码） | 同上；复验后确认存在（2 处） |
| 3 | `dsh-system-prompt` 疑似"未声明依赖" | 只匹配到注释 | 看上下文后排除：注释是"**刻意不** import" |
| 4 | `subscriptionRisk` 疑似"看板未实现 FR-110" | 只查了 `board-panel`；实际在 `node-inspector` | 扩展到全部客户端文件后排除 |
| 5 | 交接截断疑似"没给省略说明" | `grep` 命中注释而非实现 | 读函数全文后确认 `truncateUtf8` 会写 `⚠ …已截断…` |

> **教训（已写进报告，建议也写进审查规则）**：**"搜不到" ≠ "不存在"**。
> 判断某主张不成立以前，必须**读到实现本身**（函数体），并**换一种读取方式复验**。

## 6. 结论

1. **文档的机制性承诺基本都成立**：CAS、checkpoint 幂等、能力探测、确认令牌、五类拒绝原因、
   边界零 token 修正、口径串同源、29 个工具、领域 version 冻结 —— 逐项在代码里有对应实现。
2. **只有 1 处是"文档要求复用、代码自研"**（`dsh-output-retention`），另 2 处是**把流程/基准混进了需求**。
3. **全部 3 处偏差都用"改文档"处理**，理由：功能行为本身正确（截断有省略说明、性能目标未变、
   巡检确实在执行），缺陷在**文档与实现的说法不一致**，而不是行为不一致。
4. 建议把 §5.6 的复用清单升级为**"声明 → 实际引用位置"两列**，让"名义复用"无处藏身
   （本轮的偏差 1 就是这样被查出来的）。
